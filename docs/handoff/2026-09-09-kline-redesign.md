## 已确认的实现选择

1. 一次绘图或设置操作结束后立即保存本地数据和待同步记录；350ms 防抖用于网络发送。移动光标、选择对象和重新收到行情不触发保存。
2. 绘图只保存时间和价格。旧版屏幕像素绘图不做猜测转换。
3. 删除使用持久化删除记录；删除与编辑冲突保留恢复副本。显式撤销删除与普通异地编辑有不同的版本标记，避免误复活已删除对象。
4. 浏览器同步请求走现有 `/api/sync` 代理。代理保留后端 409/401 状态，供冲突重试和身份处理使用。
5. 预测沿用后端日线基线模型；周/月线不伪造三日预测。显示的 OHLC、MA、BOLL 和明细来自同一预测快照。
6. 未找到原设计的独立概念图片，视觉验收以已确认的布局说明及仓库原型为依据，不声称与缺失图片逐像素一致。

## 环境

Windows 目录权限修复后，代码、依赖和 Git 数据已移至 `E:\Code\Stock`。Git 和 Java 的直连失败通过使用系统已有代理解决；未修改全局代理配置。Java 21 工具链安装在当前用户的本地应用数据目录下。

在本机 PowerShell 中启动前端：

```powershell
Set-Location E:\Code\Stock\frontend
npm.cmd run dev -- --hostname 127.0.0.1
```

浏览器测试默认使用 Playwright 自带 Chromium；本机可通过 `$env:PLAYWRIGHT_CHANNEL = 'chrome'` 选择已安装的 Chrome。手机项目使用 Chromium 的手机视口与触控模拟，不代表经过 iOS Safari 真机验证。设置 `PLAYWRIGHT_BASE_URL` 时测试使用该地址的已有服务，否则由 Playwright 启动开发服务。

真实行情、短信、AI 和跨设备服务需要各自的后端配置。浏览器自动化使用明确标记的测试 HTTP 响应验证前端行为；这不能替代真实供应商或生产数据库联调。

交易日期沿用现有后端日历逻辑：排除周末与 `STOCKCAL_PREDICTION_EXCHANGE_HOLIDAYS` 配置的休市日。部署时必须维护覆盖预测日期的交易所休市配置；默认空配置不能保证排除法定节假日。当前 `baseline-v1` 为确定性技术推演，置信度是启发式值，未经过概率校准。

本地生产预览使用 Next.js standalone 输出；浏览器验收命令为在 `frontend` 中设置 `PLAYWRIGHT_BASE_URL=http://127.0.0.1:3000` 和 `PLAYWRIGHT_CHANNEL=chrome` 后执行 `npm.cmd run test:e2e`。
