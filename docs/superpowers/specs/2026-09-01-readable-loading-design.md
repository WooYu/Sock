# StockCal 全站简洁布局与行情加载状态设计

## 目标

让 StockCal 的网页更容易理解和操作，并修复真实行情首次加载时误显示为空行情的问题。

## 背景与现状

- `StockWorkspaceProvider` 已定义 `idle/searching/loading/refreshing/ready/stale/offline/error` 状态。
- 总览和 K 线页面目前主要用 `snapshot` 是否存在判断展示分支，因此首次请求期间会进入“真实行情暂不可用”空态。
- 刷新时 provider 会保留 `lastSuccessful`，但页面没有一致的“正在刷新 / 数据可能已过期”反馈。
- 顶部导航把分析、预测、交易、统计等二级功能全部平铺，增加了认知负担。
- 现有页面已经具备视觉 token 和 `workspace-polish.css`，本次沿用现有 token，不引入新的 UI 依赖。

## 设计

### 1. 共享行情状态组件

新增 `src/features/workspace/market-state.tsx`，提供两个纯展示组件：

- `MarketLoadingState`：按页面 variant 渲染稳定尺寸骨架，并使用 `role="status"` 和可读提示。
- `MarketFeedback`：在已有行情上叠加刷新、离线缓存、旧数据等轻量状态提示。

组件不发起请求、不持有业务状态，只消费 `WorkspaceStatus`、错误文本和重试回调，保证总览、分析、K 线的状态语义一致。

### 2. 行情状态渲染规则

| 页面数据 | 状态 | 展示 |
| --- | --- | --- |
| 无快照 | `loading` | 骨架 + “正在加载真实行情” |
| 无快照 | `idle` | 引导选择股票 |
| 无快照 | `error` | 错误说明 + 重新加载按钮 |
| 有快照 | `refreshing` | 保留旧数据 + 刷新中提示 |
| 有快照 | `stale` | 保留旧数据 + 数据可能已过期提示 |
| 有快照 | `offline` | 保留数据 + 离线缓存提示 |
| 有快照 | `ready` | 正常展示 |

真实行情请求期间禁止显示“暂无行情”“真实行情暂不可用”等终态文案。

### 3. 全站导航与布局

一级导航固定为：总览、个股分析、专业 K 线、交易、复盘、规则库。分析、交易、复盘内部的现有页签保留，由页面内部承载二级功能。

全站页面统一使用：

1. 页面标题与一句话说明；
2. 当前股票或当前任务；
3. 一个主要操作区；
4. 次要数据与历史信息。

减少重复大卡片、降低阴影和边框视觉噪声；触控按钮保持至少 44px，高频按钮使用明确主次层级。

### 4. 错误处理

- 失败且无旧行情：展示错误状态，并允许调用现有 `refresh` 重新请求。
- 失败但有旧行情：不清空内容，显示旧数据提示；刷新按钮仍可用。
- 请求被新请求取消：不显示错误。

## 验收标准

- 总览首次进入时，网络请求未返回前能看到骨架，不出现“真实行情暂不可用”。
- 分析和 K 线首次进入时，网络请求未返回前能看到骨架，不出现假空态。
- 切换股票或刷新期间，已有行情不闪退成空白，页面显示刷新反馈。
- 请求失败时，错误文案和重试操作可见，且不引入演示股票数据。
- 桌面与移动端一级导航均只展示 6 个入口；二级页面仍可通过页签访问。
- `npm test`、`npm run lint`、`npm run build` 通过。
