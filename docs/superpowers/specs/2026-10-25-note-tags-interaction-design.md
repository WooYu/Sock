# 笔记标签交互优化

## 目标与范围

针对线上 `/knowledge?view=notes`，补齐从筛选笔记、核对标签到补充预估作用定义的操作流程。保留原文依据、标签修订历史与现有共享同步机制。

## 方案

采用用户选择的完整流程优化。在现有详情中加入独立的定义编辑，不把定义塞进标签备注。仅改善布局无法解决无入口的问题；将所有内容放进标签弹窗会继续混淆两种状态。

## 页面交互

1. 目录搜索与常用筛选优先展示，其余筛选可展开；展示已选条件并支持单项移除和清空。翻页时详情与当前列表保持一致，保存后保留可继续浏览的上下文。
2. 详情保留“概览、原文与依据、版本历史”。“编辑标签”只管理分类、主题和说明，“确认标签”明确表示核对分类，不代表研究有效。
3. 每项预估作用展示用途、定义状态、原文依据及“补充定义／编辑定义”按钮。将大段原文默认折叠，保留引用位置。
4. 定义编辑提供条件或计算方法、适用周期与场景、失效或退出条件、待补问题和修订说明。支持保存草稿、字段校验、取消编辑、键盘聚焦和未保存提醒。
5. 区分“待补充定义”“定义草稿”“已定义、待验证”。编写文字不能自动获得已验证状态；现有编译规则与验证结果独立显示，不被人工草稿覆盖。
6. 保存后显示明确的成功或失败提示、版本与下一步。失败保留输入；旧版本只读。定义通过现有版本记录保存并兼容旧数据、导出及同步，避免额外的孤立存储。

## 边界

本次不新增回测引擎，不将人工定义直接接入交易或预测执行，不自动生成验证通过结果。兼容无定义的旧笔记、整篇笔记和规则片段。

## 验证

覆盖旧数据兼容、定义修订与状态、版本保留、保存冲突和失败保留输入；通过本地浏览器验证筛选、翻页、定义编辑与保存后刷新、取消与键盘操作，并检查桌面及手机布局。
