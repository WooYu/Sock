# StockCal Web-first + Next.js/Vercel 产品设计

> 状态：已确认，作为当前权威产品与技术设计。
>
> 参考基准：`docs/stockcal-redesign-prototype.html`、`docs/stockcal-prototype.css`，以及当前 `backend/` Spring Boot 服务和原 Flutter 业务实现。

## 一、路线结论

StockCal 首期以手机浏览器和桌面浏览器为主要使用入口，不把 Android/iOS 原生发布作为当前前置条件。产品采用响应式 Web/PWA 形态，优先还原参考原型的页面结构和交互，再根据真实使用频率决定是否增加原生客户端。

前端采用 Next.js App Router + TypeScript，由项目自行开发；Vercel 是可选的 Web 预览与部署平台，不是业务代码或后端的替代品。正式生产环境优先支持现有阿里云服务器，Vercel Hobby 仅用于个人非商业预览；商业化、团队协作或超出免费额度时再评估 Pro。不得因为使用 Vercel 而迁移已有 Spring Boot、PostgreSQL、Redis 或外部行情服务。

## 二、目标与非目标

### 2.1 本阶段目标

1. 手机浏览器 375px 宽度可完成搜索股票、查看行情、切换分析页签和查看 K 线。
2. 桌面浏览器 1440px 宽度呈现顶部导航、双栏/三栏工作区和完整股票上下文。
3. 总览、个股分析、专业 K 线、交易、复盘和规则库使用统一导航与当前股票状态。
4. 真实行情通过现有 Spring Boot API 访问；认证和第三方密钥只停留在服务端。
5. 所有关键路径可在本地、阿里云测试环境和 Vercel Preview 重复验证。

### 2.2 当前不做

- 不要求 Android/iOS 原生包，不维护第二套移动 UI。
- 不将 Spring Boot 业务迁移为 Vercel Functions。
- 不在浏览器保存 Tushare、OpenAI、短信等服务密钥。
- 不引入自动交易或券商下单。
- 不为了 Next.js 重写已稳定的后端领域计算；仅在需要时补充 Web DTO/API。
- 不把演示行情伪装成真实行情；演示模式必须有明确标识。

## 三、总体架构

```text
手机/桌面浏览器
        │
        ▼
Next.js App Router（SSR 页面壳 + Client 交互）
        │  同源 /api BFF，服务端注入后端地址和认证
        ▼
Spring Boot API（阿里云）
        ├─ 行情搜索/快照：/api/v1/market
        ├─ 认证/设备：/api/v1/auth
        ├─ 知识/规则：/api/v1/knowledge
        ├─ 复盘 AI：/api/v1/reviews
        └─ 同步/管理：/api/v1/sync、/api/v1/admin
        │
        ▼
PostgreSQL + Redis + Tushare/OpenAI/短信服务
```

### 3.1 前端边界

- `app/` 只负责路由、页面元数据和服务端页面组合。
- 需要搜索、切股、页签、图表绘制和弹层的组件显式标记为 Client Component。
- `src/features/` 按总览、分析、K 线、交易、复盘、规则拆分；组件只接收数据和回调，不直接访问数据库。
- `src/lib/api/` 提供类型化 API 客户端；浏览器优先调用 Next.js `/api/*` BFF，避免 CORS 和暴露后端拓扑。
- `src/lib/workspace/` 保存当前股票、周期、快照、分析和请求版本；切换页面不丢失工作区。
- 服务端只读取 `STOCKCAL_API_BASE_URL`、服务端 token 等环境变量；`NEXT_PUBLIC_*` 不放秘密。

### 3.2 后端边界

保留现有 Spring Boot 服务和领域计算。现有 `MarketController` 已提供：

- `GET /api/v1/market/search?q=`
- `GET /api/v1/market/stocks/{code}/snapshot`

Next.js 首期先代理这两个接口；组合、交易、预测、统计接口按页面实际需要增量补齐 DTO，不在前端复制账本规则。后端响应必须携带股票代码、行情时间、数据来源和新鲜度，供前端判断是否过期或离线。

## 四、信息架构与路由

### 4.1 一级入口

| 一级入口 | 路由 | 主要内容 |
|---|---|---|
| 总览 | `/overview` | 组合摘要、自选行情、提醒、最近预测 |
| 个股分析 | `/analysis/key-levels` | 关键位、盈利模式、未来指标、AI 策略 |
| 专业 K 线 | `/chart` | 周期、绘图、指标、缩放、行情图层 |
| 交易 | `/trading/positions` | 持仓、交易记录、预测记录、统计图表 |
| 复盘 | `/review/daily` | 当日、单笔、历史复盘、规则回测 |
| 规则库 | `/rules` | 经验规则、知识笔记、审批发布 |

当前股票使用可分享的查询参数 `?symbol=600519`；操作周期使用 `?cycle=short|swing|long`。页签使用路径段，刷新页面后可以恢复当前页面，不引入额外路由框架。

### 4.2 桌面导航

宽度不小于 900px 时使用 68px 吸顶顶栏：品牌、六个一级入口、全局股票搜索、提醒和账户菜单。选中入口显示蓝色底部线；搜索选股后所有页面共享该股票。内容宽度上限 1392px。

### 4.3 手机导航

宽度小于 900px 时使用轻量顶部栏和固定底部五项：`总览｜分析｜K线｜交易｜复盘`。规则库、账户、设置和后台从账户菜单进入。底部每项最小触控高度 48px；文字放大 1.3 倍时不得横向溢出。

## 五、股票工作区状态

工作区由 `StockWorkspaceProvider` 提供，使用 `useReducer` 管理状态，使用 TanStack Query 或等价的请求缓存管理异步生命周期。首期公开以下类型：

```ts
type OperationCycle = 'short' | 'swing' | 'long'
type WorkspaceStatus =
  | 'idle' | 'searching' | 'loading' | 'refreshing'
  | 'ready' | 'stale' | 'offline' | 'error'

type StockWorkspaceSnapshot = {
  symbol: string
  security: Security
  market: MarketSnapshot
  analysis: StockAnalysis
  cycle: OperationCycle
  generatedAt: string
}
```

状态必须遵守：

1. 选择新股票立即更新 `symbol`，清空当前展示快照并进入 `loading`，旧股票数据不能冒充新股票。
2. 每次请求带递增 `requestVersion` 和 `AbortController`；响应写入前同时校验版本与股票代码。
3. 刷新失败保留 `lastSuccessful`，显示「数据已过期/离线」、最后成功时间和重试操作。
4. AI 或知识服务失败只影响对应卡片；行情、指标和 K 线仍可用。
5. 搜索结果和当前股票分离；输入搜索不能重置当前分析。
6. 退出登录清除凭据与受保护远程缓存，但保留允许匿名保存的本地标注和草稿。

## 六、页面与交互要求

### 6.1 总览

展示组合指标条、持仓摘要、自选行情、关键提醒和最近预测。持仓、自选、提醒和预测行均可点击：先更新 `symbol`，再跳转到对应分析或交易页。未登录显示明确登录入口，不填充假行情。

### 6.2 个股分析

共享行情头包含股票名称/代码、现价、涨跌、开高低、成交量、换手率、行情时间、自选状态和短线/波段/中长线选择。四个页签必须保持同一工作区：

- 关键位：方向、上涨/下跌关键区、目标位、概率、依据展开和进入 K 线动作。
- 盈利模式：策略排序、匹配分数、主策略选择、买入关注、止盈和失效条件。
- 未来指标：未来三日 MA/BOLL、基准/强势/弱势路径、日周月切换；外推线与真实行情分界。
- AI 策略：数值计算→规则匹配→AI 解释，解释能回到指标、规则或历史案例；未配置或失败时显示真实状态。

### 6.3 专业 K 线

使用独立大画布。工具分为 K 线周期、绘图工具、指标设置、视图缩放、行情图层五组；绘图和指标通过弹出面板组织。支持趋势线、水平线、矩形、交易点、文字的创建、选择、拖动、编辑、撤销、重做、隐藏和删除。缩放、平移、十字光标、指标和标注共享同一坐标系。

### 6.4 交易、复盘、规则库

交易页包含持仓、交易记录、预测记录和统计图表；预测版本不可变，交易修改只影响交易账本和派生损益。复盘明确区分预测回测与实际交易复盘。规则库展示原始知识来源、结构化条件、适用周期和审批状态；只有已发布版本参与分析。

## 七、部署策略

### 7.1 阿里云生产优先

- 使用 Docker Compose 运行 Next.js、Spring Boot、PostgreSQL、Redis（按服务器资源决定是否拆分数据库）。
- Nginx 负责 HTTPS、域名、压缩和 `/api` 反向代理；前端和后端使用同源域名降低 CORS 风险。
- 真实服务密钥只写入阿里云服务端环境变量或密钥管理，不提交 Git。
- 若面向中国大陆正式运营，按域名、备案和数据合规要求办理，不因使用 Vercel 绕过阿里云要求。

### 7.2 Vercel 可选预览

- Git 分支或 Pull Request 可触发 Preview Deployment，供视觉和交互验收。
- Vercel 环境仅配置后端 API 地址和必要的公开配置；秘密不写入浏览器环境变量。
- 若使用 Vercel 构建，先执行测试和 `next build`，再部署；生产仍可由阿里云承载。
- 个人非商业阶段可使用 Hobby；商业化或团队协作时按官方套餐重新评估。

## 八、质量与验收

### 8.1 自动化

- TypeScript 严格模式、ESLint、单元测试（Vitest）和组件测试（Testing Library）。
- Playwright 覆盖 1440px 和 375px：导航、搜索选股、跨页同步、二级页签、刷新错误和 K 线工具面板。
- 每个新增状态转移先写失败测试，再写最小实现。

### 8.2 视觉

截图基线至少覆盖：1440px 总览、分析四页、K 线、交易、复盘、规则库；375×812 五个主入口、关键位展开态、K 线工具面板。检查内容层级、间距、字号、颜色、边框、状态、横向溢出和触控面积。测试通过不能代替视觉验收。

### 8.3 阶段门槛

每个阶段必须同时满足：相关测试全绿、TypeScript/ESLint 无问题、`next build` 成功、目标尺寸截图完成对照、真实操作路径无控制台错误。阿里云部署和 Vercel Preview 均不得静默使用演示行情。

## 九、实施阶段

1. **Web 基础与部署骨架**：创建 `frontend/` Next.js 应用、共享 token、测试工具、Docker/Nginx 与环境变量边界。
2. **导航与股票工作区**：完成顶部/底部导航、URL 状态、BFF、行情快照和竞态保护。
3. **总览与个股分析**：完成行情头、关键位、盈利模式、未来指标、AI 策略。
4. **专业 K 线**：完成五类工具、标注编辑、视口和图层。
5. **交易工作区**：组合、交易流水、预测记录、统计图表。
6. **复盘与规则库**：当日/单笔/历史复盘、预测回测、规则审批。
7. **整体验收与上线**：真实数据联调、阿里云生产、Vercel Preview、PWA、性能和安全检查。

## 十、旧方案处理

以下方案被本文替代：

- Flutter 作为当前首要 Web 产品实现；
- 桌面左侧 Rail 和移动 Drawer 作为主导航；
- 九个业务页面全部作为同级入口；
- 为了 Vercel 把 Spring Boot 后端整体改成 Serverless；
- 使用测试/演示行情掩盖真实数据尚未接入。

现有 Flutter 工程、计算逻辑、接口模型和历史测试保留为迁移参考；在 Next.js 首条业务链路上线前，不删除 Flutter 代码或后端实现。
