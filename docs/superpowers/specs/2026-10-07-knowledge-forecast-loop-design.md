# 知识参与价格预判：第一阶段设计

日期：2026-10-07（Asia/Shanghai）

状态：设计已整理，待用户审阅；尚未实施。

## 目标与已经确认的方向

用户希望更好地使用 `/knowledge`，把股票笔记和个人经验应用到未来价格预判。用户已认可第一阶段的三个功能：知识的结构化条件和预测用途、K 线工作台的本次适用知识、预测快照与到期复盘。

成功标准是：选定股票后能看到哪些知识适用、条件是否满足、影响哪部分判断；保存后能按当时的行情和知识版本复盘，区分价格误差、价位触达与条件失效。

本阶段采用本机研究闭环，沿用知识库当前的本地保存方式。知识编辑、预测研究记录和研究复盘可导出；跨设备云同步属于后续阶段。日线和未来三个交易日是第一阶段的计算范围。

## 当前实现与必须解决的连接

| 部分 | 当前实现 | 第一阶段的连接方式 |
|---|---|---|
| 经验库 | `knowledge-types.ts` 的 `ExperienceEntry`；固定研究资料包与本地版本账本合并 | 在知识版本上添加结构化研究定义，抽出可共享的读取与订阅服务 |
| 经验编辑 | `experience-workbench.tsx` 内部管理读取、追加版本和确认解释 | 知识详情增加研究定义编辑，编辑生成新版本，来源原文继续冻结 |
| 已发布规则 | `/api/knowledge/rules` 经 `browser-client.ts` 进入分析引擎 | 保留原有规则核验；新增经验研究结果独立展示并标明来源 |
| 研究依据 | `research-evidence.tsx` 提供走势、笔记规则和历史相似 | 增加“本次适用知识”入口，引用经验库版本和逐项核验结果 |
| 数值推演 | 后端 `PredictionService` 使用最近 20 根日线生成 `baseline-v1` | 继续作为价格基线，知识提供参考位、情景条件和资格约束 |
| 原预测记录 | `PredictionRecord` 仅存方向、关键位、理由等摘要 | 使用独立研究账本冻结完整预测与知识依据，避免把旧摘要当完整预测 |
| 复盘 | `review-page.tsx` 主要保存人工总结和交易复盘 | 增加预测研究复盘视图，按日期对照实际行情 |

经验库的“解释已确认”与后端“规则已发布”目前是两条独立链路。第一阶段必须让工作台读取经验库本身的有效版本，不能只改后端规则面板后宣称经验库已经接入。

后端当前预测响应缺少输入行情版本、复权方式及收盘完成状态。工作台还并行获取行情与预测，二者可能不是同一份输入。增加可追溯输入信息是可靠保存和自动评估的必要工作。

## 方案选择

推荐“结构化核验 + 显式参考位 + 冻结记录”。它能利用现有知识和数值基线，先建立可解释、可验证的使用链路。

纯语义问答可辅助阅读，但无法单独说明条件是否满足和预测参数从何而来。直接按经验数量调整预测涨跌幅，容易重复计票且缺乏增益证据。前两者分别作为后续辅助检索和后续模型研究，第一阶段先完成推荐方案。

知识在本阶段实际参与的输出是：适用状态、候选情景、MA5/BOLL 等参考位、行动资格及失效提示。每张记录显式保存 `numericAdjustmentApplied=false`；价格中枢和基线区间由原模型生成，区间仍是技术情景范围，不能显示成已经校准的 P10/P90。

## 一、知识的结构化研究定义

为 `ExperienceEntry` 添加可选 `researchDefinition`，旧版本没有该字段时仍能读取。其结构包括：

| 字段 | 约定 |
|---|---|
| `purpose` | 趋势判断、价位参考、波动观察、行动约束、事件提示之一 |
| `familyId` | 同义知识归并主题；重复知识保留出处，只产生一组同义输出 |
| `scope` | 明确品种、股票代码限制、日线周期与 1–3 日观察范围；用结构化值匹配 |
| `conditions` | 所有条件按 AND 核验；选择受支持事实、比较符和有限数值；不执行任意表达式 |
| `invalidationConditions` | 结构化失效条件与补充说明；能计算的单独核验，文字说明不伪装成自动判定 |
| `referenceLevels` | 从固定指标选择当前或未来指定日 MA5、MA10、MA20、BOLL 上/中/下轨、历史前高/前低 |
| `qualitativeEffect` | 看多观察、看空观察、震荡观察、限制新开多头、风险提示；不填未验证概率 |
| `assumptions` | 明确采用的代理定义，如“以收盘低于 MA5 表示破位”；与原文分开展示 |
| `unresolvedDefinitions` | 当前用途必需但尚未定义的条件，非空时该用途不能变成有效信号 |
| `researchStatus` | `draft` 或 `ready-for-observation`；表示是否可前瞻观察，不表示已有盈利优势 |

`gaps` 继续保留整条原文的缺失信息。研究定义可以只研究原文的一小部分，但必须明确其子范围及假设；该部分必需的缺失信息进入 `unresolvedDefinitions`。不能为了让条件命中而忽略相关缺失。

确认解释与确认研究定义是两个动作。修改解释、条件、范围或参考位都追加知识版本，并把研究定义恢复为 `draft`。已保存的预测仍引用旧版本。

首批整理五个主题，默认提供研究草稿，由用户核对代理定义后使用：

1. `ma5-floor`：日线收盘与 MA5 的关系，只覆盖明确选定的短线资格/底线子规则。
2. `ma20-floor`：MA20/BOLL 中轨参考及选定情景下的底线；缺少情景定义时显示条件不足。
3. `b3-r03`：MA5、MA10 同时向下的资格约束。
4. `three-day-levels` 与 `manual-levels`：同一“未来三日 MA5/BOLL 上轨参考”规则族，保留两个来源。
5. `rebound-warning`：弱势反抽 MA5 的观察；完整弱势背景尚未定义时保持待补定义。

系统不因资料包中出现可计算词语而自动确认草稿。界面提供结构化编辑，本阶段无需新增外部 AI 服务。

## 二、事实计算和本次适用知识

从冻结的日线行情统一计算事实，复用现有比较算子。提取共享事实计算函数，使后端发布规则核验和经验研究使用一致的均线及量能口径。

第一批事实：收盘与 MA5/MA20/BOLL 中轨的关系、MA5/MA10/MA20 斜率、当前量相对前 20 根有效日线均量、距 MA5/MA20 的有符号比例、最近 20 根已完成日线的最高/最低价。均线斜率为当前 SMA 减上一根 SMA。完整 20 日量比需要 21 根有效日线；数据不足保持缺失。

高周期行情、板块强弱、市场恐慌、葛兰碧阶段、热点等未取得完整定义或对应数据时保持未知。不能用日线量比代替盘中量比，不能把交易周期 `short/swing/long` 当成图表周期 `day/week/month`。

选择股票和日线原点后，按股票代码、品种、周期、知识版本生效时间及提示有效期筛选。旧的自由文本股票限制需要转换成明确代码；存在歧义的限制不能默认当作全市场。

每条知识具有一个适用状态和一组完整核验明细：

| 状态 | 含义 |
|---|---|
| `matched` | 范围适用、研究定义已确认、必需条件均满足且未触发失效 |
| `not-matched` | 已知条件至少一项不满足；仍显示同时存在的缺失数据 |
| `insufficient` | 没有已知失败条件，但必需定义或事实缺失 |
| `out-of-scope` | 股票、品种或周期不适用 |
| `expired` | 临时提示在本次原点已过期 |
| `unconfirmed` | 解释或研究定义尚未确认 |
| `invalidated` | 已满足明确的失效条件 |

优先检查范围、有效期和确认状态，然后核验失效及触发条件。只有 `matched` 产生有效研究输出。不同规则族的相反趋势观察标记冲突；行动资格约束独立展示，禁止开多不会制造看跌价格路径。

工作台显示知识名称、版本、用途、当前事实值、阈值、参考位、失效条件、原文与缺失数据。默认展示有效输出和需要补充的候选；其余结果可展开查看。知识详情深链接使用 `id` 和 `version`，能够直接打开引用的历史版本。

## 三、预测来源与输入一致性

预测响应增加可选 `basis`，保留现有字段以兼容旧客户端。`basis` 从本次实际送入 `PredictionService` 的行情生成，不能根据另一条请求事后猜测：

- 股票、日线周期、行情提供方、获取时间、最后输入日、输入是否为已完成日线。
- 复权口径：`none/qfq/hfq/unknown`。无法从提供方确认时记录 `unknown`。
- 实际参与价格和量能核验的最近 21 根有效日线副本；少于 21 根时保留实际数量与缺失事实。
- 输入规范化算法版本与 SHA-256；按日期排序、固定字段和数值序列化规则，前后端共享测试向量。
- 最后输入收盘价、预测目标日期、生成时间、模型版本和交易日历口径。

研究核验优先使用预测的 `basis`，主图继续使用自己的行情数据。若图表与预测输入不一致，明确标记各自截止日期，不能将新行情的核验结果拼到旧预测上。

旧响应没有 `basis` 时继续显示原有价格推演；允许保存“来源待核实”的观察记录，并保存当时所见行情及其独立来源。此类记录不自动计算价格误差或纳入有效样本统计，直到有可追溯依据；不能通过推测的原点补成正式样本。

日线盘中数据只作为临时观察。完成状态由提供方元数据或交易日历结合明确的收盘后数据口径确定；单凭客户端时间超过 15:00 不足以确认。状态不明时保持未知，记录可保存但不进入正式前瞻样本。

## 四、保存预测研究记录

在日线工作台提供“保存本次预测”。显式保存让每张记录代表用户愿意跟踪的一次观察，刷新行情不会自动产生新账本条目。

新增独立 IndexedDB 研究账本，以事务保证追加和重复保存检查。原知识本地账本继续可读，研究记录不使用会覆盖旧数组的通用 `saveRecords`。保存成功前按钮显示进行中；配额、权限、格式或写入失败保持当前输入并报告失败。

`ForecastResearchSnapshot` 包括：

- `id`、schemaVersion、createdAt、股票、日线周期、原点及输入可信状态。
- 行情来源、复权、输入副本及 hash、模型/指标/核验版本、目标日期和完整原预测值。
- 原点收盘、当前与预测参考位及其用途；某指标缺失时保存缺失原因。
- 引用的知识全文版本快照、出处、结构化定义、逐项核验、规则族、冲突及缺失条件。
- 输出作用列表及 `numericAdjustmentApplied=false`。

完整语义载荷生成去重指纹，排除保存时间、请求获取时间、预测生成时间和随机 ID，保留原点、行情内容、模型输出及知识内容。同股票、同原点、同输入、同模型输出、同知识与核验内容的重复点击返回原记录；条件或预测变更时追加新记录，不覆盖原记录。旧资料包更新后，预测仍能够查看当时的知识内容。

导出研究 JSON 包含 schemaVersion、导出时间、预测记录、评价版本及内容摘要；研究页支持验证后导入。导入逐条校验并事务合并，相同 ID 不同内容报冲突并保留现有记录。知识库继续使用其现有导出格式。

本机记录在同一浏览器和站点有效。界面提供简短存储说明和导出入口。示例 DEMO 使用独立空间，其记录与真实统计分开。

## 五、到期复盘与评估口径

复盘工作台增加“预测研究”入口，对应 `/review/forecast`，显示待到期、部分到期、已完成、数据不足和来源待核实记录。用户访问研究复盘页或手动刷新时获取所需历史日线并核对；本阶段不建立后台定时任务或关闭浏览器后的自动执行。

原预测永久冻结。`ForecastResearchEvaluation` 作为独立、追加的评价版本，保存 evaluatedAt、实际行情来源/口径/哈希、逐日结果、缺失或排除原因和评价算法版本。行情修订后追加评价，保留旧评价。

| 评价项 | 定义 |
|---|---|
| 收盘误差 | `predictedClose - actualClose`；同时显示绝对误差和 `abs(error)/actualClose` |
| 方向 | 预测/实际收盘相对原点收盘的符号；相等为持平，方向误差与价格误差分别展示 |
| 基线区间覆盖 | 当日实际收盘是否落在冻结的 `rangeLow..rangeHigh`；同时记录相对区间宽度 |
| 参考位触达 | 事前为指定日期生成的参考位是否落在该日实际最低与最高之间；表示价位被覆盖 |
| 条件失效 | 冻结失效条件能否在到期实际数据上核验；文字条件或数据缺失保持未知 |
| 人工观察 | 可追加原文理解、适用范围或数值幅度的纠错说明；不自动重写知识定义 |

每个目标日期单独评估，等三个日期都具备已完成且可比的数据后才显示“已完成”。因停牌、节假日配置或缺失行情不存在的目标日不能用下一根日线替换；保留具体日期及原因。

评估要求输入和实际价格口径可比。复权未知、原点未知、停牌、数据未完成或除权导致不可比时，列明原因，不纳入汇总。未复权记录跨除权时，仅在确认期间无价格口径变化或取得可靠可比资料后进入正式评价。

汇总同时显示有效原点数量、各预测跨度的有效样本数、排除原因与日期范围。同一原点的多个版本可逐张查看；默认统计选该原点最早保存、来源可核实的预测，避免把反复刷新视为独立样本。样本少时继续显示原始结果，标注尚未验证，不显示规则有效性等级。

触达不是成交或收益；涨跌方向命中不是价格误差改善。第一阶段记录经验的适用、触达与失效结果，但没有经验调整价格的数值实验，因此不宣称已经测得知识带来的价格预测增益。

## 验收和必要验证

1. 旧知识账本和资料包可正常读取；结构化字段保存后追加版本，修改恢复待确认，旧版本可定位。
2. 用固定行情检查均线、斜率、量比、范围、过期、失效和缺失状态；缺数据不能变成满足条件。
3. 同族经验只产生一组参考输出，保留全部原文；相反观察可看到冲突，资格约束不改变价格路径。
4. 选股、快速切股、延迟预测响应和知识更新时，只展示对应股票/输入/版本的结果；不把旧响应绑定到新行情。
5. 来源输入 hash 的前后端测试向量一致，未知口径可见，缺 `basis` 的旧响应继续正常显示。
6. 多次保存和多标签页保存不覆盖记录；失败不提示成功；重新打开可恢复，并能导出、校验后导入。
7. 知识修订、模型更新及评价数据修订后，旧预测、旧依据和旧评价内容保持可查。
8. 对价格误差、持平方向、区间覆盖、逐日参考位触达、条件失效和停牌/缺失日期进行独立计算验证。
9. 验证跨复权/除权、未知原点、未完成日线和 DEMO 不进入正式统计；同原点多版本不重复计独立样本。
10. 桌面和手机完成“编辑研究定义 → 确认 → 选股核验 → 保存 → 复盘”的端到端流程，检查键盘交互和原文深链接。
11. 实施后运行前端测试、lint、build，运行涉及后端元数据的测试；故障与兼容用例通过后再准备部署结果。

## 实施顺序与后续阶段

先建立共享知识读取和结构化版本；再统一事实计算并接入研究依据；补齐预测输入来源；接着完成事务账本和到期评价；最后验证完整桌面/手机流程。

云端知识同步、独立任务调度、语义检索服务、分位数模型、经验数值加权、多股票滚动回测和交易执行分别是后续工作。部署需在实现与验证完成后，以具体构建结果确认；当前文件是第一阶段设计产物。

## 设计自查

- 目标、日线三日范围、存储位置和用户操作已经明确。
- 知识确认、研究观察和已验证优势分别表达。
- 图表/预测的并行请求、版本冻结和未知来源都有具体处理。
- 条件核验、参考位触达和价格误差使用独立口径。
- 旧数据兼容、追加存储、导入冲突和失败反馈均有验收项。
- 没有待定占位，后续功能与第一阶段范围分开。
