# StockCal 统一交易工作台设计规范

## 文档状态

- 日期：2026-09-07
- 状态：待用户确认后进入实施计划
- 替代方案：本规范替代 `2026-09-04-stockcal-trading-workspace-design.md` 中按页面使用 `cyber / chart / feed` 三套视觉语言的方案

## 目标

将 StockCal 统一为一套“浅色专业交易终端”界面，使首页、分析、专业 K 线、规则、交易、复盘和设置像同一个产品，同时保留不同任务需要的信息密度。

本轮聚焦界面体系、布局、可读性和响应式交互，不改变已经完成的规则执行语义、真实行情协议、自然周/月聚合、预测计算和绘图数据模型。

成功标准：

1. 用户在任意页面都能识别相同的导航、按钮、面板、表单和状态反馈。
2. 桌面端保留专业分析密度，手机端仍可在单手操作下完成查看、分析、规则启停和复盘。
3. 页面正文、辅助信息和触控区域达到既定可读性要求。
4. 统一视觉不牺牲 K 线、规则和分析的现有功能。

## 设计原则

### 1. 同一系统，不同密度

所有页面共享颜色、字体、圆角、边框、阴影、控件状态和导航结构。K 线可以比规则页更密集，但不得拥有独立皮肤；规则和复盘可以更偏表格与表单，但不得退化为社交信息流。

### 2. 决策优先

页面首先回答“当前是什么状态、为什么、下一步能做什么”。装饰不能压过行情、规则结论、风险和主要操作。

### 3. 保守表达

涨跌色只用于行情语义；蓝靛色用于选中和操作；琥珀色用于警告、等待与冲突。禁止用大量高饱和颜色伪造重要性。

### 4. 状态可见

加载、空数据、失败、禁用、保存中、保存成功、规则缺失和规则冲突都必须有明确界面状态，不能用空白或只有颜色的方式表达。

## 视觉系统

### 色彩令牌

| 令牌 | 建议值 | 用途 |
|---|---:|---|
| `--sc-canvas` | `#F5F7FA` | 页面背景 |
| `--sc-surface` | `#FFFFFF` | 面板、弹窗、表格 |
| `--sc-surface-muted` | `#F8FAFC` | 次级区域、表头、工具组 |
| `--sc-border` | `#D8DEE8` | 默认边框与分隔线 |
| `--sc-border-strong` | `#C6CEDA` | 聚焦或强调分隔 |
| `--sc-text` | `#172033` | 主文字 |
| `--sc-text-secondary` | `#526079` | 次级文字 |
| `--sc-text-muted` | `#718096` | 辅助说明 |
| `--sc-primary` | `#4F46E5` | 主操作、选中、链接 |
| `--sc-primary-hover` | `#4338CA` | 主操作悬停 |
| `--sc-primary-soft` | `#EEF2FF` | 选中背景、信息提示 |
| `--sc-up` | `#DC2626` | A 股上涨、卖出风险语义 |
| `--sc-down` | `#059669` | A 股下跌、买入机会语义 |
| `--sc-warning` | `#D97706` | 等待、冲突、条件缺失 |
| `--sc-danger` | `#DC2626` | 校验失败、破坏性操作 |

不得继续以 `.sc-tone-cyber`、`.sc-tone-chart`、`.sc-tone-feed` 改变整页主题。旧类可以在迁移期保留为无视觉差异的兼容钩子，最终由统一 token 接管。

### 字体与数字

- 字体栈：`Geist, Inter, "PingFang SC", "Microsoft YaHei", sans-serif`。
- 页面标题：24–28px / 700。
- 区块标题：16–18px / 600–700。
- 正文、按钮、表格：桌面和手机均不低于 14px。
- 辅助说明：不低于 12px；行情工具栏优先 13px。
- 行情价格和关键数字使用等宽数字特性 `font-variant-numeric: tabular-nums`。
- 禁止遗留 7–11px 的业务文字；图表坐标轴在空间有限时可使用 11–12px，但必须保持可辨认。

### 形状、层级与间距

- 基础间距以 4px 为单位，常用间距为 8 / 12 / 16 / 24px。
- 输入框、按钮和紧凑面板使用 6–8px 圆角；大型内容面板不超过 12px。
- 默认面板只使用 1px 边框，不叠加重阴影；弹窗和浮层使用轻量阴影。
- 桌面控件高度 36–40px；手机主要控件与可点击行至少 44px。
- 内容最大宽度由统一应用壳控制，专业 K 线可以占满可用工作区。

### 图标

- 全站使用同一套线性图标，推荐沿用现有图标依赖，不混入 Emoji 或不同笔画图标。
- 常规图标 18–20px，手机底部导航 22–24px。
- 图标按钮必须带可访问名称和 44px 手机热区；不能仅以颜色表达状态。

## 应用壳与导航

### 桌面

顶部应用栏固定承载：品牌、`首页 / 分析 / 规则 / 复盘 / 设置`、全局搜索或当前股票入口、通知和账户。当前页使用蓝靛文字与 2px 下划线，不按页面切换导航配色。

页面标题区采用统一结构：

1. 左侧为页面名称和一句辅助说明。
2. 右侧为当前页面的主要操作。
3. 标题区下方才出现筛选、标签或工具栏。

### 手机

- 顶部栏只保留页面标题、返回/搜索和一项主要操作。
- 底部固定五项导航，顺序与桌面一致；图标和文字都显示。
- 底部导航为白色表面、顶部细边框和安全区内边距，不使用悬浮胶囊。
- 页面内容必须预留底部导航空间，禁止最后一个操作被遮挡。

## 共享组件

### Button

统一为 `primary / secondary / ghost / danger` 四种层级，支持默认、悬停、按下、聚焦、禁用和加载状态。同一操作在不同页面不得出现不同形状或不同主色。

### Panel

统一白色表面、细边框、8–12px 圆角。面板标题、辅助操作和内容区使用固定结构。避免每一条信息都成为独立大卡片。

### Tabs 与 Segmented Control

- 页面任务切换使用下划线 Tabs。
- 日/周/月等短选项使用 Segmented Control。
- 选中状态统一为蓝靛色；焦点环清晰可见。

### Form

标签置于字段上方；必填、说明、错误和字符计数位置一致。错误同时包含图标/文字和边框，不只变红。保存操作应反馈保存中、成功或失败。

### Table / Compact List

桌面使用表格，手机转换为紧凑列表。选中行使用淡蓝背景和左侧强调线；状态、开关和操作保持对齐。

### Badge 与 Alert

- Badge 仅表达短状态，如 `已发布`、`完整`、`WAIT`。
- Alert 用于可行动的信息，如规则冲突、条件缺失、行情过期。
- `WAIT / 不可判断` 使用琥珀色，不与涨跌或主要操作混淆。

### Skeleton / Empty / Error

行情、规则和复盘列表共享骨架、空状态和错误状态的视觉语法。骨架尺寸应接近真实内容，错误状态必须提供重试入口。

## 页面设计

### 首页与分析

桌面采用“自选列表 + 决策中心 + 上下文信息”的工作区：

- 自选列表显示股票、最新价、涨跌幅和分析状态。
- 决策中心突出股票名称、当前价、`买入 / 卖出 / 等待 / 不可判断`、置信信息和更新时间。
- 关键价位、信号证据、风险提示使用结构化区块，而非装饰性大卡片。
- 右侧展示市场状态、规则命中和最近复盘等上下文。
- “进入专业 K 线”与主要分析动作使用统一按钮层级。

手机按“股票概览 → 决策 → 关键价位 → 信号证据 → 风险提示”纵向排列。关键结论在首屏可见，细节通过可点击行或折叠区展开。

### 专业 K 线

保留 TradingView 式图表优先布局，但完全采用统一色彩和控件：

- 顶部第一行显示股票、最新价和核心行情；第二行分组展示周期、指标、绘图、缩放和图层。
- 图表面积最大化；蜡烛、MA、BOLL、成交量、十字光标和价格标签保持清晰。
- 左侧绘图工具栏与右侧图层/分析检查器使用统一面板和图标按钮。
- 买卖、目标、止损、水平线和趋势线标注继续显示对应价格。
- 预测路径必须与真实行情在颜色、线型和图例上区分。
- 图层关闭后，相关图形与读数按既有功能契约处理，不改变计算逻辑。

手机首屏保留股票、价格、日/周/月和图表；指标、绘图、缩放与图层进入名为“图表工具”的底部抽屉。抽屉按功能分组，每行至少 44px，关闭后恢复完整图表高度。

### 规则库

桌面采用“筛选与表格 + 详情检查器”：

- 标题区提供 `新建规则` 和 `导入 Markdown`。
- 搜索与 `已上线 / 待审核 / 经验概念 / 已拒绝` 共享统一统计来源。
- 表格显示规则名、周期、模式、条件完整性、状态、启用开关和操作。
- 选中规则在右侧详情检查器中展示条件、有效期、优先级、标签、冲突与启用状态。
- `参与个股分析` 必须明确对应持久化的启用状态。
- 新建规则使用弹窗或右侧抽屉；空条件在字段下方显示 `规则条件不能为空`，并禁用提交。

手机使用紧凑规则列表；详情和新建进入底部面板。启用开关、详情入口和保存动作均满足 44px 热区，底部主操作保持可见。

### 复盘

使用统一任务 Tabs：`当日总结 / 单笔复盘 / 历史复盘 / 规则回测`。

- 当日总结按 `市场判断 / 执行情况 / 改进点` 分区，按钮统一为 `保存复盘`。
- 表单不使用过度大圆角或彩色渐变按钮。
- 历史数据、预测快照和回测状态使用表格或紧凑列表。
- 规则回测尚未具备真实绩效时，只显示数据准备状态和入口，不展示伪造收益数据。

手机 Tabs 可横向滚动，主要保存操作在键盘未弹出时保持易达，但不得遮挡输入内容。

### 交易工作区

交易工作区在主导航中归属于 `复盘`，内部使用 `持仓 / 交易流水 / 预测记录` 三个任务 Tabs。进入交易子页面时，桌面顶部导航和手机底部导航都应保持 `复盘` 选中，避免新增第六个一级入口。

桌面采用“汇总与表格 + 详情检查器”：

- 标题区显示 `交易工作区`、记录同步状态和主要操作 `记录交易`。
- 持仓页先展示持仓股票、累计投入和待复盘交易三个紧凑摘要，再展示股票、数量、成本价、最新价、浮动盈亏和操作表格。
- 选中持仓后，右侧检查器展示数量、平均成本、最新价及 `查看个股分析 / 打开 K 线 / 去做复盘`。
- 交易流水按日期展示买卖方向、股票、数量、成交价格和复盘状态。
- 预测记录展示方向、置信信息、支撑、压力、目标和关联复盘状态，不展示未经真实数据计算的收益。
- 新增交易使用弹窗或侧边面板，字段为交易方向、股票代码、数量、成交价格和备注；校验错误显示在对应字段下方。

手机使用单列摘要和紧凑列表；`记录交易` 保持在首屏可达位置。新增交易进入底部面板，主要保存按钮位于面板底部但不得被软键盘或系统安全区遮挡。交易流水的 `去做复盘` 和预测记录的 `关联复盘` 均应具备完整文字与 44px 热区。

### 设置

设置页使用与复盘相同的表单与状态组件。行情源、连接状态和账户信息按设置组组织；危险操作独立放在末尾并使用 danger 层级。

## 响应式规则

| 断点 | 布局 |
|---|---|
| `>= 1280px` | 三栏首页/分析，K 线带左右辅助栏，规则表格加详情检查器 |
| `1024–1279px` | 两栏布局，右侧检查器可收起或覆盖 |
| `640–1023px` | 单主栏加可展开辅助区，表格减少次要列 |
| `< 640px` | 单列、底部导航、表格转列表、工具和详情使用底部抽屉 |

通用要求：

- 页面不得产生非图表用途的横向溢出。
- 安全区、软键盘、底部导航和固定操作不能互相遮挡。
- 弹窗与抽屉支持 Esc、遮罩关闭、焦点锁定和关闭后焦点归还。
- 指针、键盘和触控能够完成同一核心任务。

## 迁移策略

### 阶段 1：统一基础层

1. 建立全局 design tokens、字体和语义色。
2. 统一应用壳、桌面顶部导航和手机底部导航。
3. 建立 Button、Panel、Tabs、Form、Badge、Alert、Skeleton 等共享样式。
4. 消除 `.sc-tone-cyber / chart / feed` 的视觉分叉。

### 阶段 2：迁移核心页面

1. 首页和分析迁移为统一决策工作区。
2. 专业 K 线统一工具栏、侧栏和手机工具抽屉。
3. 规则库迁移为表格/列表加详情检查器。
4. 交易工作区迁移为汇总、表格/列表和详情检查器。
5. 复盘与设置迁移为统一表单和状态布局。

### 阶段 3：可读性与回归

1. 清理业务界面的 7–11px 字体和不足 44px 的手机热区。
2. 补齐加载、空、失败、保存和校验状态。
3. 完成桌面/手机浏览器截图对照与功能回归。

迁移过程中每个页面保留现有功能和数据契约，避免以一次大范围 DOM 重写同时改动业务逻辑。

## 不在本轮范围

- 不实现新的规则执行算法或真实历史回测引擎。
- 不改变行情数据源、后端接口或数据库结构。
- 不重写图表引擎、自然周/月聚合或绘图坐标模型。
- 不新增深色模式、赛博主题或多主题切换。
- 不引入伪造行情、收益或规则命中数据。

## 验收标准

### 视觉一致性

1. 首页、分析、K 线、规则、交易、复盘和设置共享同一画布、面板、边框、主色、字体、按钮和状态组件。
2. 不再出现可感知的赛博页、Twitter 信息流页和独立 K 线皮肤。
3. 桌面正文/按钮不低于 14px，辅助信息不低于 12px；手机正文和按钮不低于 14px。
4. 颜色、圆角、阴影和间距与已确认概念稿一致。

### 功能保持

1. 首页与分析仍能加载真实行情并给出保守规则结论。
2. K 线骨架、日周月、MA/BOLL、图层、缩放、十字光标、绘图工具、买卖与价格标注全部可用。
3. 规则统计与列表一致，新建、导入、审核、发布、启停和持久化不回归；已启用完整规则真正参与分析。
4. 持仓、交易流水、预测记录、新增交易和关联复盘可用，记录同步入口不回归。
5. 复盘保存、历史列表和规则回测入口可用。

### 响应式与可访问性

1. 390px 宽度下无页面级横向溢出，底部导航和固定操作不遮挡内容。
2. 手机主要热区至少 44px；工具抽屉、规则详情和表单可以触控完成。
3. 键盘焦点可见，弹窗/抽屉焦点行为正确，核心控件具有可访问名称。

### 验证方式

1. 为设计 token、应用壳、导航和关键响应式组件补组件测试。
2. 保留并扩展规则、分析与 K 线现有交互测试。
3. 运行完整前端测试、ESLint 和 Next.js 生产构建。
4. 以 1440px 桌面和 390px 手机浏览器截图逐页对照概念稿，人工核对字号、布局、溢出和交互状态。
5. 浏览器回归覆盖首页、分析、K 线、规则、交易、复盘和设置的主要任务链路。

## 已确认视觉概念摘要

- 首页/分析：浅灰画布、白色工作面板、左侧自选、中央决策、右侧上下文。
- K 线：浅色图表优先工作台、分组工具栏、图层检查器、OHLC 十字光标和带价标注。
- 规则/复盘：专业表格与结构化表单，不使用社交信息流布局。
- 交易：桌面持仓表格与详情检查器，手机交易流水列表和新增交易底部面板。
- 手机：首页纵向决策流、K 线工具底部抽屉、规则详情底部面板，以及统一五项底部导航。
